# 実機確認手順（Lightroom Classic / macOS）

対象: `papat-lightroom-1.0.1.zip`（`scripts/package.sh` で作成）、`papat-lightroom-1.0.1.pkg`（`scripts/build-pkg.sh`）。
自動テスト（`scripts/check.sh`）では Lightroom 本体の挙動は確認できません。ここに挙げた項目を実機で見てください。
各項目は ☐ に ✓ を付け、✗ のときは「見たこと」を書き留めてください。ログは `~/Documents/LrClassicLogs/papat-lightroom.log`
（API キー・パスコードは入りません）。

準備:
- テスト用カタログ（実案件ではないもの）。JPEG と RAW が数十枚。RAW+JPEG が同名で入っている組も数組
- papat.app にログインでき、ダッシュボードで API キーを発行できること（キーはチャット等に貼らない）
- クライアント役のブラウザ（別ブラウザ or シークレットウィンドウ）

## A. インストール

- ☐ A1 ZIP を解凍すると `papat.lrplugin` フォルダと `はじめにお読みください.txt`（文字化けしない）ができる
- ☐ A2 `shasum -a 256 -c papat-lightroom-1.0.1.zip.sha256` が OK
- ☐ A3 ファイル → プラグインマネージャー → 追加 → `papat.lrplugin` で「インストール済みで実行中」になる
- ☐ A4（別途）`~/Library/Application Support/Adobe/Lightroom/Modules/` に置いて再起動すると自動で読み込まれる（A3 と二重登録にならないこと）
- ☐ A5 ライブラリ → プラグインエクストラに「papat でギャラリーを作る…」「papat のセレクトを読み込む…」が出る
- ☐ A6 メタデータパネルのプリセットに「papat」が出る

## B. API キー

- ☐ B1 キー未設定でギャラリー作成を実行 → 「API キーが設定されていません」と手順が出る。「ダッシュボードを開く」でブラウザが開く
- ☐ B2 ダッシュボード（papat.app/app）でキーを発行し、プラグインマネージャーに貼り付けて「保存」→ 表示が「設定済み（••••••••末尾4桁）」になり、全桁は出ない
- ☐ B3 「接続を確認」→「接続できました。アカウント: …」
- ☐ B4 わざと間違ったキー（例 `sk_live_x_y`）→ 保存で形式エラー／存在しないキー形式で接続確認 → 401 の案内（日本語）
- ☐ B5 Lightroom を再起動してもキーが残っている（末尾4桁が表示される）
- ☐ B6 「削除」でキーが消える
- ☐ B7 機内モード等でオフラインにして「接続を確認」→「接続できませんでした…」（クラッシュしない）

## C. ギャラリーを作る

3枚程度で確認 → 問題なければ 100枚前後で確認。

- ☐ C1 写真を3枚選んで実行 → ダイアログ（タイトル初期値＝選択中のフォルダ/コレクション名、7日、パスコード6文字が自動入力、目安 88円）
- ☐ C2 「14日」にすると目安が 176 円になる。パスコードを3文字にすると赤字の注意が出て「作成して送信」が押せない
- ☐ C3 「作成して送信」→ 進捗（書き出し→送信）が出る。右上の ✕ でキャンセルでき、キャンセル後に説明が出る
- ☐ C4 完了ダイアログに URL・パスコード・公開期限・案内文が出る。案内文は「写真をお送りします。／タイトル／URL:／パスコード:／公開期限: ○月○日まで／ブラウザで開いて…『確定』を押してください。」の構成で、「登録は要りません」を含まない
- ☐ C4b ダッシュボード（papat.app/app）のそのギャラリーで、**パスコードが確認できる**（プラグインで入力・生成したものと同じ）
- ☐ C5 papat.app のダッシュボードにギャラリーが現れ、枚数が正しい
- ☐ C6 URL をクライアント用ブラウザで開くとパスコード入力 → 入力後に写真が表示される。縦横比・向き・クロップが Lightroom の現像結果どおり
- ☐ C7 クライアントに届く JPEG が長辺 2048px で、sRGB。著作権・作成者・連絡先は入り、GPS・シリアル番号・現像設定などは入らない（確認は O 章）
- ☐ C8 14日を選んだ場合、公開期限が約14日後になる（サーバー側が未対応で7日になった場合は完了画面に注意書きが出る）
- ☐ C9 完了後、選んだ写真のメタデータパネル（プリセット「papat」）に「papat ギャラリー」が入っている。レーティング・ラベル・キーワード・説明は変わっていない
- ☐ C10 送信中にネットワークを切って戻す → 自動で1回再試行される／失敗分の再送ダイアログが出る
- ☐ C11 100枚前後でもメモリ・待ち時間が許容範囲（目安: 数分以内）。レート制限（429）のときは「少し待つ」だけで最後まで進む
- ☐ C12 一時ファイル（`$TMPDIR/papat-…`）が完了後に残っていない
- ☐ C13 **クライアントの色（任意）**: ダイアログに「色（任意）」の1行だけがある（項目が増えすぎていない）。空欄のまま作成 → ギャラリーが papat の標準色（`#E0452B`）で表示される
- ☐ C14 `#0066CC` を入れて作成 → クライアント用ブラウザで、ギャラリーの差し色（ボタン・★・選択枠）が青系になり、文字が読める（白/黒の自動選択）
- ☐ C15 `0066cc`（`#` なし）でも受け付けて `#0066cc` として送られる。`blue` や `#06c` など `#RRGGBB` 以外は赤字の注意が出て「作成して送信」が押せない
- ☐ C16 一度使った色が「最近使った色…」のメニューに出る（最大5件、新しい順）。選ぶと入力欄に入る
- ☐ C17 ダッシュボード（papat.app/app）のそのギャラリーの色が、プラグインで指定した色と同じ

## D. 案内文のコピー

- ☐ D1 完了画面を開いた直後にクリップボードに案内文が入っている（テキストエディタに貼り付けて確認）。文字化けしない
- ☐ D2 「案内文をコピー」「URL をコピー」「パスコードをコピー」が、それぞれ該当の文字列を入れる
- ☐ D3 「ブラウザで開く」でギャラリーが開く
- ☐ D4（コピーに失敗した場合）案内文欄を選択して Cmd+C でコピーできる。→ 失敗した場合は `clipboard: …` のログ行を控える

## E. クライアントとして選ぶ

- ☐ E1 別ブラウザで URL・パスコードを入力して入る
- ☐ E2 数枚に「採用」、うち数枚に ★1〜★3、タグとメモを付ける（同じ写真に複数）
- ☐ E3 「確定」を押す → 写真家（あなた）にメールが届く

## F. セレクトを読み込む

事前に、読み込む写真の一部へ ★4 と赤ラベル、説明（Caption）に「元の説明」を付けておく。

- ☐ F1 「papat のセレクトを読み込む…」→ ギャラリー一覧が出る（タイトル・期限・枚数）。終了済み/期限切れは出ない
- ☐ F2 選ぶと確認ダイアログに「採用した写真 N 枚／見つかった写真 N 枚」「反映する内容」（コレクション・採用フラグ・メモ追記・タグ）が出る
- ☐ F3 「コレクションに追加」→ コレクション「papat 採用 〈ギャラリー名〉 〈作成日〉」ができ、採用写真だけが入る
- ☐ F4 **採用フラグ**が採用写真に付く（付かない場合は log の `setRawMetadata(pickStatus) failed` を控える）
- ☐ F5 **メモ→説明**: 元の説明が残り、末尾の新しい行に `— papat: 〈メモ〉` が足される（説明が空だった写真は `— papat: 〈メモ〉` だけ）
- ☐ F6 **タグ→キーワード**: キーワード「papat」の下にタグができ、写真に付く。書き出し対象のキーワードになっていない
- ☐ F7 **レーティングとカラーラベルが変わらない**（事前に付けた ★4・赤ラベルのまま）
- ☐ F8 **同じギャラリーをもう一度読み込む** → コレクションが増えない／写真が重複しない／**メモが二重に追記されない**（説明の `— papat:` 行が1つのまま）
- ☐ F9 クライアントがメモを変えて再確定 → 再読み込みで新しいメモの行が追記される（古い行は残る）
- ☐ F10 設定（プラグインマネージャー）を確認し、既定が「採用フラグ＝オン／メモ追記＝オン／タグ＝オン／★サブコレクション＝オフ」になっている
- ☐ F11 設定で各項目をオフにして読み込む → オフにした項目だけが反映されない（コレクション追加は常に行われる）
- ☐ F12 ★サブコレクションをオン → コレクションセット「papat 〈ギャラリー名〉 〈作成日〉」の下に「採用」「★3」「★1」…ができ、★ごとの写真が入る

## G. 照合

- ☐ G1 プラグインで作成したギャラリー → 記録した ID で全件一致する（ファイル名を変更した写真でも一致）
- ☐ G2 別カタログ（記録なし）で読み込む → ファイル名（拡張子を除く）で一致する。「RAW+JPEG が同名」の組は「複数あり反映しない」に出る
- ☐ G3 カタログに無い写真は「見つからなかった写真」に一覧される
- ☐ G4 まだ誰も採用していないギャラリー → 「まだ採用された写真がありません」

## H. エラー表示

- ☐ H1 無料枠（8ギャラリー）を超えたとき、「カードを登録してください」の案内が出てダッシュボードに飛べる（課金 ON 後に確認）
- ☐ H1a ギャラリーを作る画面の「目安 88 円（税込）」の横に「無料の残り N ギャラリー」が出る（N はダッシュボードの無料の残りと同じ。作成するたびに 1 減る。0 のときは「無料の残りはありません」）。通信できないときは、無料の話は出ない
- ☐ H2 通信不可 → 「接続できませんでした」。クラッシュや英語のエラーが出ない
- ☐ H3 キーを失効させて実行 → 「API キーが正しくないか、無効」
- ☐ H4 公開中のギャラリーが10件ある状態で作成 → 「公開中のギャラリーが上限の10件に達しています…」（409 `active_gallery_limit`）。「すでに終了しています」ではないこと。ダッシュボードを開くボタンが出る

## I. 実機で決着させたい SDK の不確定事項

Lightroom の SDK ドキュメントでは断定できず、実機で確認が必要な項目です。✗ のときの切り替え先も書いてあります。

| # | 確認すること | 想定 | ✗ のとき |
|---|---|---|---|
| I1 | `LrExportSession:renditions()` のループだけで書き出しが走る | 走る（`waitForRender` で待つ） | `export.lua` を `doExportOnCurrentTask()` ＋書き出しフォルダの列挙に変更 |
| I2 | 書き出し設定 `LR_size_resizeType='wh'`＋2048×2048 で長辺2048になる | なる | `LR_size_resizeType='longEdge'` と `LR_size_longEdge` に変更 |
| I3 | 書き出しの設定（`LR_removeLocationMetadata` ほか）で、Lightroom が出す一時ファイルのメタデータが小さい | 効く（効かなくても、送る前に `lib/jpeg.lua` が取り除き、`lib/rights.lua` が入れ直す。ログの `metadataRemoved=` に取り除いた数が出る） | 影響なし |
| I4 | クリップボード（`LrClipboard` は SDK に無い想定 → `pbcopy`） | pbcopy 経由でコピーできる | 案内文の欄を手動コピー（実装済みの代替） |
| I5 | `LrHttp.post(..., 'PUT')` で JPEG をそのまま PUT できる | できる | `LrHttp.postMultipart` へ変更（サーバー側の対応も必要） |
| I6 | `pickStatus` に数値 1 を書ける | 書ける | `LrSelection.flagAsPick()` 経由（選択の変更が必要） |
| I7 | `catalog:batchGetPropertyForPlugin(photos, _PLUGIN, …)` / `findPhotosWithProperty` | 動く | 写真ごとの `getPropertyForPlugin` に変更 |
| I8 | `LrPasswords.store(key, '')` で削除できる | できる | 空白1文字を保存して未設定扱い |
| I10 | 複数の `LrHttp.post` が、複数の `LrTasks.startAsyncTask` から**同時に**進む（ネットワーク待ちの間に他の送信が動く） | 動く（M6 の並列の目安） | `pipeline.DEFAULT_CONCURRENCY` を 1 にする |
| I11 | `photo:requestJpegThumbnail(2048, 2048, cb)` が長辺最大2048pxのJPEGを返す（速さ優先） | 返る | 速さ優先は使わない（設定はオフのまま） |
| I12 | `photo:getRawMetadata('uuid')` / `catalog:findPhotoByUuid` | 動く（続きから送る） | 「続きから送る」は同じ選択からのやり直しになる |
| I9 | メタデータパネルのプリセット「papat」（`LrMetadataTagsetFactory`） | 出る | `Tagset.lua` の項目 ID を確認（`app.papat.lightroom.papatSid`） |

## K. インストール場所（1.0.1）

- ☐ K1 ダウンロードフォルダの `papat.lrplugin` を「追加」で読み込む → プラグインマネージャーの先頭に「インストール場所」が出て、現在のパスと「ダウンロードフォルダから読み込まれています」の注意が赤字で出る
- ☐ K2 その状態でメニュー「papat でギャラリーを作る…」を初めて実行 → 「標準の場所にコピーしますか？」が**一度だけ**出る（「今はしない」にして、もう一度実行しても出ない）
- ☐ K3 「標準の場所にコピー…」→ 確認ダイアログ（今の場所／標準の場所）→「コピーする」→ 「コピーしました…再起動してください」と手順が出る
- ☐ K4 Finder で `~/Library/Application Support/Adobe/Lightroom/Modules/papat.lrplugin` ができ、`Info.lua` と `lib/` がある。`.DS_Store` は入っていない
- ☐ K5 もう一度コピーを実行 → `~/Library/Application Support/Adobe/Lightroom/papat-lightroom-backups/papat.lrplugin.<日時>` に前のものが退避され、Modules の中に古いファイルが残らない
- ☐ K6 Lightroom を再起動 → papat が読み込まれ、「インストール場所」が「標準の場所から読み込まれています」になる。元のフォルダを消しても動く
- ☐ K7 一覧に papat が2つ並ぶ場合の表示・「削除」ボタンの有効/無効（元の場所のほうが削除できるか）を控える
- ☐ K8 標準の場所のプラグイン（.pkg で入れたもの、または K3 でコピーしたもの）では、「インストール場所」の警告も「標準の場所にコピー…」ボタンも出ず、バージョン欄に「標準の場所にインストールされています。」の1行だけが出る（1.0.1 の不具合の再確認）

## L. インストーラ（.pkg。署名・公証済みのもの）

`docs/guide-signing.md` の④と同じ。✗ のときは見たことを控える。

- ☐ L1 ダブルクリックで Gatekeeper の警告が出ない（`spctl -a -vv -t install <pkg>` が accepted / Notarized Developer ID）
- ☐ L2 インストール先の選択が出ない。管理者パスワードを求められない
- ☐ L3 完了画面に再起動・プラグインマネージャー・API キーの案内（日本語。システムを英語にすると英語）
- ☐ L4 `~/Library/Application Support/Adobe/Lightroom/Modules/papat.lrplugin` ができる
- ☐ L5 2回実行すると、前のものが `papat-lightroom-backups/` に退避される
- ☐ L6 Lightroom 再起動後、papat が「インストール済みで実行中」。「インストール場所」が標準の場所になっている

## M. 速度・バックグラウンド送信（1.0.2）

100〜300枚で確認。時間は完了画面（または「最近のギャラリー」）に出る一行を控える:
`書き出し ○分○秒（○秒/枚）／送信 ○分○秒（○秒/枚・3並列）／全体 ○分○秒`。ログ `papat-lightroom.log` の `pipeline:` 行にも同じ値が残る。

- ☐ M1 「作成して送信」の直後（数秒以内）に、URL・パスコード・案内文のウィンドウが開く（書き出しの完了を待たない）。案内文はクリップボードに入っている
- ☐ M2 ウィンドウの「閉じる（送信は続きます）」を押しても、Lightroom 左上に papat の進捗が出て、書き出し・送信が続く。**その間、ライブラリ・現像など他の操作ができる**
- ☐ M3 ウィンドウを開いたままのときは、下の欄の「送信中… x / N 枚」が更新される
- ☐ M4 クライアント用ブラウザで URL を開く → 送信の途中でも、届いた写真が表示される。**再読み込みで写真が増えていく**（自動では増えない場合は、サーバー・クライアント画面の対応が必要。Issue またはメンテナーへ報告）
- ☐ M5 完了時に小さな通知「papat: N 枚の送信が完了しました」。ダッシュボードの枚数が N と一致する
- ☐ M6 書き出しと送信が並行している（左上の進捗で、書き出し済みの数と送信済みの数が同時に増える）。送信が3本同時に動いている（ログの `x3` と、1枚あたりの秒数 × 枚数 ≒ 全体時間 × 3）
- ☐ M7 300枚で、従来（1.0.1。約10分）と比べた所要時間を控える
- ☐ M8 途中で左上の ✕ で中断 → 「送信を中止しました」。メニュー「papat 最近のギャラリー…」に「送信済み x / N 枚。残り … 続きから送る」が出る
- ☐ M9 「続きから送る」→ 残りだけが送られ（重複して送られない）、完了後にダッシュボードの枚数が N になる
- ☐ M10 送信の途中で Lightroom を終了 → 再起動して同じカタログを開き、「最近のギャラリー」→「続きから送る」で残りを送れる
- ☐ M11 「最近のギャラリー」で URL・パスコード・案内文が再コピーできる（日本語が文字化けしない）
- ☐ M12 ネットワークを切って戻す → 自動で再試行／失敗分の再送ダイアログが出る。429（レート制限）は待って再試行され、最後まで進む
- ☐ M13 全部の写真が書き出せない場合（ファイルが見つからない等）は、作成したギャラリーが取り消される（ダッシュボードに残らない）
- ☐ M14 **速さ優先**をオンにして同じ写真を送る → 所要時間（「プレビュー取得」の秒数）と、画質・色・サイズを書き出し版と見比べる（クライアント画面で拡大して比較）。プレビューが小さい写真が小さく届かないか
- ☐ M15 プレビューが無い写真（未生成）がある場合も、書き出しに切り替わって全件届く

## N. 更新のお知らせ（1.0.2）

古い版を入れた状態（例 1.0.1）で、サーバーの最新版を上げて確認する。サーバー側の設定変更が必要。

- ☐ N1 サーバーの最新版 > 手元の版 のとき、「papat でギャラリーを作る…」で「papat の新しいバージョンがあります」が出る（現在の版と最新版、更新の手順つき）。「ダウンロードページを開く」で https://papat.app/lightroom/ が開く。「あとで」で閉じ、そのまま処理が続く
- ☐ N2 同じ日にもう一度メニューを実行しても、お知らせは出ない（1日1回まで）。翌日（またはプラグインを入れ直さずに時計を1日進めて）に再び出る
- ☐ N3 「セレクトを読み込む…」「最近のギャラリー…」でも同じお知らせが出る（1日1回の枠は共通）
- ☐ N4 サーバーの最低対応版 > 手元の版 のとき、「papat の更新が必要です」が出て、ギャラリー作成・セレクト読み込みが**実行されない**。何度実行しても毎回出る。「最近のギャラリー」は、お知らせだけで一覧は開ける
- ☐ N5 機内モード（通信不可）でメニューを実行しても、更新に関する表示は出ず、動作が止まらない。待たされない（数秒以内）
- ☐ N6 プラグインマネージャーの「接続を確認」の表示が、上の判定と一致する（任意の更新は「新しいバージョンがあります」、必須は「更新が必要です」）
- ☐ N7 **更新の実行**: .pkg をダブルクリックして上書き → Lightroom を再起動 → API キーが入ったまま（再入力不要）、「最近のギャラリー」が残っている、`papat-lightroom-backups/` に古い版が退避されている

## P. 速さ優先モード：カタログの状態（1.0.3）

速さ優先をオンにして、結果の表示（完了画面・「最近のギャラリー」）の「プレビューから N 枚・書き出しで M 枚」と、
ログ `pipeline images:` 行の `previewRejected=[…]` を控える。仕組みは `docs/fast-mode.md`。

- ☐ P1 **標準プレビューが無い写真**: 新しく読み込んだだけ（まだ表示していない）写真 3〜5 枚を送る。
  → 速さ優先の結果か、「書き出しで」になるか。所要時間（プレビュー取得の秒/枚）を控える
- ☐ P2 **「埋め込みとサイドカー」で読み込んだカタログ**: 読み込みのプレビューを「埋め込みとサイドカー」にして RAW を数枚読み込み、
  表示せずに送る → `previewRejected=[embedded=…]` が出るか。出ない場合は、届いた JPEG を `exiftool -a -G1 -s` で見て、
  Exif があるか（あれば「プラグインが見逃した」ので報告）
- ☐ P3 **現像を変えた直後**: 1 枚の露光量を +1.0 にして、すぐに速さ優先で送る → ギャラリーの見た目が Lightroom の
  表示と合っているか（古い見た目なら報告）
- ☐ P4 **標準プレビューサイズ**: カタログ設定 → ファイル管理 → 標準プレビューサイズを 1440 にして送る
  → `previewRejected` に `small` が出て書き出しに切り替わるか。「自動」「2880」でも同じに（`large` になるか）
- ☐ P5 **スマートプレビューのみ**: 外付けドライブを外して（元ファイルがオフライン）、スマートプレビューのある写真を、
  通常と速さ優先でそれぞれ送る → 届くか、長辺は何 px か
- ☐ P7 **標準プレビューサイズごとの大きさと時間**（速さ優先）: カタログ設定 → プレビュー → 標準プレビューサイズを
  1024・1440・1680・2048・2880・自動 に変えながら、各 3〜5 枚を送り、ログの `probe photo` 行（大きさと秒数）と
  `pipeline images:` 行（`longEdge=` `avg=`）を控える。1024・1440・1680 は「その場で作られる」ので、
  秒数が 0.8 秒を超えて書き出しに切り替わるか（`previewRejected=[slow=1]` と、結果の「プレビューを使えなかった」）
- ☐ P8 **プレビュー画質**: 低・中・高 で同じ 5 枚を送り、1 枚あたりのサイズ（`avg=`）と見た目の差を控える
- ☐ P9 **明るさの差の原因**（速さ優先と通常の書き出しで、同じ写真の平均の明るさが 4〜7% 違う件）:
  差が出た写真と出なかった写真で、次を比べる。(a) 現像の更新日時（直近に編集した写真か）、(b) 現像のコピー元（プリセット・カメラプロファイル）、
  (c) 差が「影」「中間」「ハイライト」のどこに出るか（10・50・90 パーセンタイルの明るさ）。
  最初に、差が出た 3 枚を選び、ライブラリ → プレビュー →「標準サイズのプレビューを作成」を実行してから、もう一度速さ優先で送る。差が消えれば、
  プレビューが古かった（検知する手段は無いため、既定にしない理由になる）
- ☐ P6 **動画を含めて選ぶ**: 動画が 1 本混ざった選択で送る → 「動画 N 本は送っていません」と出て、写真だけが届く

## Q. 撮影時刻と並び（1.0.3）

2 台のカメラの写真を混ぜた 10〜20 枚で。選択の順は、わざとばらばらにする（時刻順にしない）。

- ☐ Q1 ギャラリーを「撮影時刻 ↑」で並べると、2 台のカメラの写真が撮影時刻順に混ざる。サムネイルに出る「時:分」が、Lightroom のメタデータパネルの撮影時刻と同じ（カメラの時計の時刻）
- ☐ Q2 同じ 5 枚から、続けて 2 つのギャラリーを作る（速さ優先と通常、または同じ方法で 2 回）。**2 つのギャラリーで、並びが同じ**
- ☐ Q3 撮影時刻のない写真（スキャン・合成）が混じっていても、並びが毎回同じ（時刻のある写真のあと、ファイル名順）
- ☐ Q4 「撮影時刻を編集」で片方のカメラの時刻を合わせた写真を送る → ギャラリーの時刻が、編集後の時刻になっている
- ☐ Q5 「グループ」表示（撮影時刻での区切り）で、連続した撮影が1つのグループにまとまる（バラバラに割れない）
- ☐ Q6 送信の途中で中断して「続きから送る」を使っても、最終的な並びが同じ

## O. メタデータ（1.0.3）

Lightroom の「メタデータ」パネルに、著作権・作成者・連絡先（住所・電話・メール・Web）と、位置情報（GPS）を登録した写真 3 枚で。
新しいギャラリーに送り（通常の書き出し）、ブラウザで 1 枚保存して調べる。速さ優先をオンにして同じ手順も行う。
`exiftool` が無ければ `brew install exiftool`（または https://exiftool.org/）。

```sh
exiftool -a -G1 -s ファイル.jpg
```

- ☐ O1 **初回の確認画面**: 初めて送るとき、「画像に入れる情報の確認」に、登録した著作権・作成者・連絡先が出る。
  「位置情報、カメラのシリアル番号、現像設定は入りません」と書かれている。「この内容で送る」で進む。次に同じ内容で送るときは出ない。
  連絡先を変えると、また出る。「入れずに送る」「キャンセル」も試す（キャンセルでギャラリーは作られない）
- ☐ O2 **入るもの**: 出力に、`[IFD0] Artist`・`Copyright`（Exif）と、`[XMP-dc] Rights`・`Creator`、`[XMP-xmpRights]`、
  `[XMP-iptcCore] CreatorCity`・`CreatorWorkEmail`・`CreatorWorkTelephone`・`CreatorAddress` ほか（登録したもの）が出る
- ☐ O3 **入らないもの**: `[GPS]`、`SerialNumber`・`LensSerialNumber`・`Make`・`Model`・`Software`、`RawFileName`、
  `History`（xmpMM）、現像設定（`Exposure2012` ほか `[XMP-crs]`）、`[IFD1]`（サムネイル）、`[MakerNotes]`、`[ExifIFD]`（撮影情報）が**出ない**
- ☐ O4 `ProfileDescription` が `sRGB IEC61966-2.1`（通常の書き出し）または `sRGB IEC61966-2.1 (papat)`（速さ優先）。長辺は 2048〜2560px
- ☐ O5 設定で「画像に、著作権情報・作成者・連絡先を入れる」をオフにして送ると、O2 の項目が出ない（O3 のとおり、それ以外も無い）
- ☐ O6 ギャラリーに「撮影者 ★★★」（Lightroom のレーティング）が表示され、「撮影者レーティング ↓」で並べ替えられる。
  設定で「撮影者の★をギャラリーに表示する」をオフにすると、表示されない。Lightroom 側の★は変わっていない
- ☐ O7 ログ（`~/Documents/LrClassicLogs/papat-lightroom.log`）の `pipeline images:` 行の `metadataRemoved=[…]` と `rightsAdded=` を控える
  （`metadataRemoved` に `exif`・`xmp`・`iptc` が出ていれば、Lightroom が書いたものを取り除いたという意味で、正常です）
- ☐ O8 （exiftool が無い場合）`strings -n 4 ファイル.jpg | grep -E 'GPS|Serial|crs:|History'` が何も出ない。
  macOS のプレビュー →「ツール → インスペクタ → Exif／IPTC」に、作成者と著作権が出る

## R. ベータでの確認（画面で見るものだけ。1.0.3）

数値（届いた画像のメタデータ・大きさ・プロファイル、manifest の撮影時刻・★・並び）は別に確かめる。ここは画面で見るもの。

- ☐ R1 作成して送信 → **数秒で URL・パスコード・案内文**が出る。ウィンドウを閉じても、Lightroom 左上に進捗が出て、他の操作ができる
- ☐ R2 初めて送るとき**「画像に入れる情報の確認」**が出る。登録した著作権・作成者・連絡先が読める。「入れずに送る」「キャンセル」も効く
- ☐ R3 送信が終わると小さな通知。「最近のギャラリー」に、URL・パスコード・秒数の行（書き出し／送信／全体）が残る
- ☐ R4 ブラウザのギャラリーを「撮影時刻 ↑」で並べる → 2 台のカメラの写真が時刻順に混ざり、サムネイルの「時:分」が Lightroom と同じ
- ☐ R5 ギャラリーに「撮影者 ★」が Lightroom の★どおりに出る。設定でオフにすると消える（Lightroom の★は変わらない）
- ☐ R6 送信の途中で左上の ✕ で中断 →「最近のギャラリー」→「続きから送る」で残りだけが届き、並びが崩れない
- ☐ R7 速さ優先をオンにして送る → 結果に「プレビューから N 枚・書き出しで M 枚」。設定画面の説明に「現像を変えたあとは、プレビューが古いままのことがある」がある
- ☐ R8 現像（露光量 +2）を変えた直後に、表示せずに速さ優先で送る → ギャラリーの明るさが変更後か（古ければ報告）
- ☐ R9 4 件目以降のギャラリー作成（課金 ON）→「カード登録が必要です…」と出て「ダッシュボードを開く」が使える。登録後に作成できる
- ☐ R10 設定画面（プラグインマネージャー → papat）で、標準の場所なら「標準の場所にインストールされています。」の 1 行だけ。節が「接続」→「アタリ送付」→「セレクト受け取り 反映設定」→「バージョン」の順で、「アタリ送付」に 3 つのスイッチ（★・著作権等・速さ優先）がある
- ☐ R11 「papat でギャラリーを作る」の冒頭の説明が、2 行で最後まで読める（途中で切れない）。速さ優先をオン／著作権等をオフにしたとき、枚数が 3 桁のときも同じ。完了後の画面・「最近のギャラリー」・セレクトの確認画面・設定画面の説明文も、末尾まで読める

## S. インストーラーの使用許諾（署名なしの .pkg で確かめる。1.0.3）

画面でしか確かめられないもの。**インストールまでは進めない**（使用許諾の画面で止めて閉じる）。署名なしの .pkg（`scripts/build-pkg.sh` が `dist/unsigned/` に作る）を使う。

開き方: ターミナルで `open dist/unsigned/papat-lightroom-<バージョン>-unsigned.pkg`。Finder のダブルクリックで「開発元を確認できません」と出たら、右クリック → 開く。
（AirDrop・ダウンロードで受け取った場合は隔離属性が付くので、右クリック → 開く、または `xattr -d com.apple.quarantine <pkg>`。）

- ☐ S0 題のすぐ下に「**第1版　2026年10月12日**」（英語表示は「Version 1 — October 12, 2026」）が出る。日本語と英語で版・日付が同じ
- ☐ S1 「はじめに」→ **「続ける」**を押すと、「使用許諾契約」の画面が出る。日本語（システムが日本語のとき）で、題が「papat for Lightroom Classic のご利用にあたって」
- ☐ S2 本文が「1. 料金」から「7. ソースコード」まで読める。リンク（papat.app・利用規約・プライバシーポリシー）を押すとブラウザで開く
- ☐ S3 下までスクロールすると、**MIT License**（英語の原文）が読める。文字化け・切れ・`&amp;` などの崩れがない
- ☐ S4 「続ける」→ **「同意する」「同意しない」「使用許諾を読む」**の選択が出る。「同意しない」を押すとインストールが始まらずに終われる
- ☐ S5 **暗い表示**（システム設定 › 外観 › ダーク）にして開き直す。背景と文字の色が合っていて読める（白地に白字・黒地に黒字になっていない）。明るい表示でも読める
- ☐ S6 英語表示で、英語の使用許諾が出る（システム設定 › 言語と地域で English を先頭にしてから開く。または
  `/System/Library/CoreServices/Installer.app/Contents/MacOS/Installer -AppleLanguages '(en)' <pkg>` — 後者が効くかは未確認）
- ☐ S7 ウィンドウの大きさのまま、「3. プラグインが送るもの」まで 1 画面に入るか（スクロールが要るかを控える。要ってよい）
